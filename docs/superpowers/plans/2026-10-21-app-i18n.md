# Estori in Spanish and Portuguese Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Estori's signed-in app, sign-in pages, server messages, seller emails and AI replies work in English, Latin American Spanish and Brazilian Portuguese, chosen by the seller.

**Architecture:**
- **Strings:** English stays in the code as the key, wrapped in `t()`, `tn()`, `msg()` or `<T>`. Per-language JSON catalogs map the English to Spanish and Portuguese.
- **Runtimes:** the browser lazy-loads one catalog. The Worker bundles both and translates at the response boundary, using a request-scoped locale.
- **Tooling:** a Babel-parser extractor feeds a completeness test and a coverage test, so nothing ships half-translated.

**Tech Stack:** React 19, TypeScript, Vite, Hono and Workers, vitest-pool-workers (`@babel/parser` is already available), `Intl`, and date-fns locales. No new i18n library.

**Spec:** `docs/superpowers/specs/2026-10-21-app-i18n-design.md`

**Code rules:**

**Languages:**
- `en` (default, English is the key), `es` (Latin American Spanish, "tú"), `pt-BR` (Brazilian Portuguese, "você").
- Formatting locales: `en` → `en-US`, `es` → `es-419`, `pt-BR` → `pt-BR`.
- Names shown in the picker: "English", "Español", "Português (Brasil)".

**Never translated:**
- brand names: Estori, Basic, Pro, Premium;
- user content: store names, messages, file names;
- code identifiers and URLs;
- legal documents.

**Strings and catalogs:**
- Placeholders are `{name}`. Tags in rich text are `<link>…</link>`-style.
- A plural key is `singular|plural` with `{ one, other }`.
- Catalogs: `shared/i18n/catalogs/es.json` and `shared/i18n/catalogs/pt-BR.json`, keys sorted.
- Every new `t`, `tn`, `msg` or `<T>` string gets its Spanish and Portuguese translation in the same task, following `shared/i18n/glossary.md`.

**Money and layout:**
- Money stays in USD, using `Intl` currency defaults: "$49", "USD 49", "US$ 49".
- Translated text must fit. No fixed widths that clip; buttons may wrap.

**Out of scope:**
- marketing pages (landing, pricing, features, industries, solutions, blog, platform, creators);
- legal documents;
- admin pages;
- `src/routes/chat/components/debug-panel.tsx`;
- generated sites and stores;

**Interfaces:**

In `locales.ts`:
```ts
export const LOCALES = ['en', 'es', 'pt-BR'] as const;
export type Locale = (typeof LOCALES)[number];
export const DEFAULT_LOCALE: Locale = 'en';
export const LOCALE_NAMES: Record<Locale, string>; // English, Español, Português (Brasil)
export const LOCALE_AI_NAMES: Record<Locale, string>; // English, Latin American Spanish, Brazilian Portuguese
export const INTL_LOCALE: Record<Locale, string>; // en-US, es-419, pt-BR
export function isLocale(value: unknown): value is Locale;
export function negotiateLocale(preferred: readonly string[]): Locale;
export function localeFromAcceptLanguage(header: string | null): Locale;
```
- `negotiateLocale` uses the first match: `es*` → `es`, `pt*` → `pt-BR`, `en*` → `en`.
- `localeFromAcceptLanguage` parses q-values, then negotiates.

In `translate.ts`:
```ts
export type CatalogEntry = string | { one: string; other: string };
export type Catalog = Readonly<Record<string, CatalogEntry>>;
export type MessageValues = Readonly<Record<string, string | number>>;
export function interpolate(text: string, values?: MessageValues): string;
export function translate(catalog: Catalog | null, english: string, values?: MessageValues): string;
export function translatePlural(catalog: Catalog | null, locale: Locale, singular: string, plural: string, count: number, values?: MessageValues): string;
export function msg(english: string): string;
export function pluralKey(singular: string, plural: string): string;
```
- `translatePlural` provides `{count}` itself, formatted with `INTL_LOCALE`.
- `msg` returns its argument unchanged; it exists only to mark strings for the extractor.
- `pluralKey` returns `` `${singular}|${plural}` ``.

In `rich-text.ts`:
```ts
export type RichPart = string | { tag: string; children: RichPart[] };
export function parseRichText(text: string): RichPart[];
```
It handles `<tag>…</tag>` with nesting, and unknown or unclosed tags as plain text.

Formatters gain an optional last parameter `locale: Locale = DEFAULT_LOCALE`, with existing outputs unchanged for `en`:
- `formatUsd`
- `formatCredits`
- `formatBillingDate`
- `formatTemplatePrice` (its "Free" goes through `translate` with a catalog argument; read the call sites and pick the cleanest way: pass `t` or return a key)

### Task 2: Extraction, completeness and coverage tooling

**Files:**
- Create:

  - `scripts/i18n-extract.ts`: writes new keys to both catalogs with an empty value and prints missing and unused keys;

  - `src/i18n-coverage.test.ts`.
- Modify: `package.json`, adding `"i18n:extract": "bun scripts/i18n-extract.ts"`.

**Interfaces:**
```ts
export interface ExtractedMessage { key: string; plural?: { singular: string; plural: string }; file: string; line: number; }
export function extractMessages(source: string, file: string): ExtractedMessage[];
export interface UntranslatedText { file: string; line: number; text: string; }
export function findUntranslatedText(source: string, file: string): UntranslatedText[];
```
- `extractMessages` finds:
  - `t('…')`, `t(locale, '…')` and `tn('…','…',n)` with literal arguments;
  - `msg('…')`;
  - `<T text="…">`.
- `findUntranslatedText` reports:
  - JSX text with letters;
  - string literals in the JSX attributes `title`, `placeholder`, `aria-label`, `alt` and `label`;
  - literal first arguments of `toast(…)`, `toast.success`, `toast.error`, `toast.warning` and `toast.info`;
  
  each one outside `t()`. A `{/* i18n-ignore */}` JSX comment, or a `// i18n-ignore` line comment directly above, skips one line, for brand names or code-like text.
- `src/i18n-coverage.test.ts` holds `const COVERED: string[]`, a list of folder and file globs, starting empty. Every later task adds its folders. The test reads the covered files with `import.meta.glob('?raw')` and fails on any `findUntranslatedText` hit.
- `i18n-catalogs.test.ts` reads every source file under `src/`, `shared/` and `worker/` (not tests) and extracts the keys. It fails when:
  - a key is missing or empty in `es.json` or `pt-BR.json`;
  - a catalog has a key no source uses;
  - placeholder sets (`{x}`) or tag sets (`<x>`) differ between the English key and a translation;
  - a plural entry lacks `one` or `other`.

**Interfaces:**
- `t(english, values?)`, `tn(singular, plural, count, values?)` and `getLocale()` read the current locale and catalog from a module singleton. The provider sets them.
- `useI18n(): { locale: Locale; setLocale(locale: Locale): Promise<void>; t: typeof t; tn: typeof tn }` subscribes, so components re-render when the language changes.
- `<T text="…" values={…} components={{ link: (children) => <a …>{children}</a> }} />` renders `parseRichText(translate(…))`.
- `setLocale`:
  1. loads the catalog;
  2. updates the singleton;
  3. re-renders;
  4. sets `document.documentElement.lang`;
  5. stores `localStorage['estori:locale']`, wrapped in try/catch;
  6. if signed in, calls `PUT /api/user/locale`.
- **Initial locale:**
  1. `user.locale`, once the profile loads;
  2. else `localStorage['estori:locale']`;
  3. else `negotiateLocale(navigator.languages)`.
- **Register** sends `locale` with the sign-up request. The server stores it when `isLocale`.
- **`PUT /api/user/locale`** takes body `{ locale }` and answers `{ locale }`. It is authenticated and CSRF-checked like other writes, and gives 400 for unknown values.
